# Native close and Quit gap

The pinned Rune version does not provide a close or Quit veto through `App::on_close`. Its callback takes `fn(&mut S, &mut Tx)` and has no result that cancels the close. See `crates/rune/src/app.rs` in the pinned Rune source. `window/lifecycle.rs` calls the hook and then hides or closes the window. `window/any_host.rs` marks a host finished before its termination hook and skips the hook for an already hidden keep-running window.

Moss's Cmd+W and Cmd+Q handlers check `flush_current()` in the current window. A normal window close keeps the process and state alive, so a failed draft can remain in memory. A native Quit can end the process after a failed flush. Cmd+Q also does not check drafts in other workspace windows, including hidden windows. Those drafts can be lost. The observed Review-app reopen is not evidence that Quit failed; the capture may have relaunched the app or returned a stale state.

The smallest safe fix needs a Rune change, not a new disk-backed recovery system: add a cancellable pre-close and pre-termination callback, and make application Quit ask every live workspace state to flush before any host is marked finished. If any flush fails, keep the process and affected windows available with the existing error and Retry/Discard controls. Preserve current Cmd+W behavior and the rule that closing all windows keeps scheduled work running. Tests must cover a visible window, a hidden window, multiple workspaces, failed flush, retry, native close, native Quit, and successful Quit. A recovery file alone cannot guarantee safety if the same disk failure prevents writing it.

Implementation ownership needs coordination: Rune's `app.rs`, `window/lifecycle.rs`, `window/any_host.rs` and termination coordination need a pinned Rune patch; Moss's `crates/moss-app/src/main.rs` needs the all-window flush gate. No patch has been made in this study.

Rune custom menu items do not replace the native defaults. The default macOS Quit item in both Rune and winit sends AppKit `terminate:`. In winit 0.30.13, the application delegate implements `applicationWillTerminate:` but not a cancellable `applicationShouldTerminate:` callback. A custom menu item alone therefore cannot cover the Dock or operating-system termination. An AppKit delegate proxy could intercept termination without copying the full framework, but it would be macOS-specific and would depend on winit delegate behavior. A coordinated Rune and winit patch is the portable path for the application-level gate, with a macOS-specific integration for native termination. The estimated change is several small framework files and roughly 100–250 lines plus lifecycle tests; this is not a measured patch size.
