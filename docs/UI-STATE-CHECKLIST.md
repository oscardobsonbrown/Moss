# Retained UI state checklist

Use this checklist to plan reference study and Moss acceptance. It is not a claim that Moss passes. A reference for one control does not cover its family. For each applicable control, test at rest, hover, pressed, keyboard focus, selection, disabled, empty, error and operation failure. Also test open/closed, loading, success, dismissal, recovery and drag where they apply. Record trigger, result, focus and persistence separately. Test light and dark, pointer and keyboard, screen-reader labels, focus return, narrow window and long content. A still cannot establish motion or latency.

`O` means a named reference state was observed, with the limits in its source. `AX` means accessibility evidence only; it does not establish visual style. `U` means the listed state is not established by the cited sample. `B` records an access blocker. The local `research/notion/STATE-MATRIX.md`, `FRONTIER.md`, capture logs and [reference coverage](REFERENCE-COVERAGE.md) contain steps and version details. Raw captures are private. These examples are not complete inventories.

Form, AI, Mail, separate Calendar, Sites, team administration, account and sync are outside the retained v1 scope. Do not turn reference-only controls into acceptance requirements. The required behavior for local storage, schedules, notifications, search, performance and portability is specified in the PRD; a missing Notion capture does not remove those requirements.
